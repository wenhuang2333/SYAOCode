# 五、业务规则文档

业务规则（BR）是约束系统行为的确定性规则，独立于具体实现，由设计落地、由测试验证。错误码的完整定义见「九、错误体系专项设计」。

## 5.1 权限与安全规则

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-001 | 权限判定优先级为 deny > ask > allow。无规则匹配时，按权限模式的默认值处理：default 模式下写类与执行类为 ask，只读类为 allow | 拒绝时返回 `SY-PERM-001`，用户拒绝返回 `SY-PERM-002` | FR-040/041/044 |
| BR-002 | bypass 模式只能由用户级配置或代码显式启用，项目级配置不得启用；启用时在 session.start 事件中记录 | 忽略项目级设置并告警 `SY-CFG-001` | FR-041 |
| BR-003 | 路径须先 realpath 解析（含符号链接），落在工作区根或额外允许目录内才可免确认访问，否则降级为 ask | `SY-PERM-003` | FR-042 |
| BR-004 | 修改已存在文件前，本会话内必须已读取过该文件，且文件的修改时间与内容哈希自读取后未变 | `SY-FS-001`、`SY-FS-002` | FR-030/031/032/047 |
| BR-005 | `edit` 的 old 字符串必须唯一匹配；多处匹配时返回匹配数量与位置提示，要求补充上下文或显式 `replace_all` | `SY-FS-003`、`SY-FS-004` | FR-032 |
| BR-006 | 危险命令（递归删除根或家目录、强制推送、格式化磁盘、写系统目录等）默认 deny，仅用户级规则可放行 | `SY-PERM-004` | FR-035/043 |
| BR-007 | 来自工具结果、网页、MCP 返回的内容均视为不受信数据：其中的指令不得改变权限判定，也不得自动授予权限 | 发出 `security.injection_suspected` 事件 | FR-036/046/101 |
| BR-023 | 日志、事件、会话文件、错误信息写入前必须经过脱敏器，匹配已知密钥模式与已配置的密钥值 | 命中时替换并记录 `SY-SEC-001`（info 级） | FR-045/060/121 |
| BR-024 | 配置优先级：代码 > 环境变量 > 项目 > 用户 > 默认；deny 规则跨层取并集，项目级不得放宽用户级 deny | 冲突项忽略并告警 | FR-040/051/120 |

## 5.2 循环与工具规则

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-008 | 同一轮多个工具调用：只读且标记并发安全的并行执行；写类工具按调用顺序串行；回填顺序与调用顺序一致 | - | FR-004/020 |
| BR-009 | 每个 tool\_use 必须恰好对应一个 tool\_result；被拒绝、中断、出错的调用也必须回填结果，保证历史对任何 provider 都合法 | 中断以 `SY-LOOP-003` 回填 | FR-002/005 |
| BR-010 | 默认最大轮次 100，可配置；预算（token、费用）用尽即停止发起新的模型调用；用量达 80% 时发出 `budget.warning` | `SY-LOOP-001`、`SY-LOOP-002` | FR-006/016/112 |
| BR-011 | 同工具同规范化参数连续失败 3 次注入提示，5 次终止 | `SY-LOOP-004` | FR-007 |
| BR-012 | 工具结果超过阈值（默认 30,000 字符或 2,000 行）时截断，保留头尾，附带「已截断」说明与继续读取方式 | `SY-TOOL-005`（warning 级，不中断） | FR-023/035/054 |
| BR-025 | 对外只允许抛出 SyaoError 体系的错误，含 code、category、retryable；禁止裸 `Error` 与字符串；校验失败返回结构化信息以便模型自我纠正 | `SY-INT-001` | FR-003/022/024 |

## 5.3 模型与上下文规则

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-013 | 上下文使用达窗口 80% 触发自动压缩。压缩必须保留：系统提示、项目指令、待办、已修改文件列表、用户最初目标、最近 6 轮原文。压缩失败则回退为清理旧工具结果，仍超限则终止 | `SY-CTX-001`、`SY-CTX-002` | FR-052/053 |
| BR-014 | 429、5xx、网络错误按指数退避重试（基数 1s，倍数 2，带抖动，最多 5 次），遵守 Retry-After；401、400 不重试；流中断且尚无已提交的工具调用时可重试 | `SY-PRV-001`～`SY-PRV-007` | FR-011/012/013/015/017 |
| BR-015 | 能力降级：不支持并行工具则串行；不支持 thinking 则忽略相关配置并告警；缺少必需能力（如不支持 tool use）时在创建 agent 时失败 | `SY-PRV-006` | FR-010/011/014 |

## 5.5 MCP、插件、钩子与子 agent 规则

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-017 | MCP 工具统一命名为 `mcp__{server}__{tool}`，server 名称规范化；与内置工具重名时内置优先 | 冲突项跳过并告警 | FR-021/070/071/074 |
| BR-018 | MCP 工具默认 ask 级别，除非 server 配置声明 trust 或被规则放行；工具注解（如只读提示）仅作参考，不用于自动放行 | `SY-PERM-001` | FR-071/072/076 |
| BR-019 | 插件须在清单中声明所需权限（fs、net、exec、env）；未授予的能力加载时拒绝；插件异常被隔离，连续 3 次失败自动禁用 | `SY-PLG-004`、`SY-PLG-005` | FR-090/091/092/093 |
| BR-020 | 插件以 semver 范围匹配 `engines.syaocode`，不匹配则拒绝加载 | `SY-PLG-002` | FR-090/094 |
| BR-021 | 钩子按配置顺序执行；PreToolUse 钩子的 deny 优先于一切 allow 规则；钩子超时默认 10s，按 failMode 处理，默认 fail-closed（阻断） | `SY-HOOK-001`、`SY-HOOK-002` | FR-040/100 |
| BR-022 | 子 agent 权限不得超过父 agent；工具集为父集合的子集；默认最大嵌套深度 2；仅向父返回最终摘要 | `SY-PERM-001` | FR-103 |

## 5.6 决策层规则（v0.3 新增）

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-026 | 决策层只产出建议，不授予权限。任何 allow 必须同时通过确定性权限引擎；BR-001 的 deny 与 BR-006 的危险命令不得被决策层覆盖 | 视为缺陷，由测试强制 | FR-140/143/146 |
| BR-027 | 非对称原则：决策层默认只能收紧（allow 改为 ask，ask 改为 deny）。决策模型本身永远不能授予权限。只有当用户级策略事先明确授权某类低风险调用可自动批准、确定性权限引擎已将该调用标记为可自动审批候选、调用位于工作区内且不属于危险命令时，经过校准的 enforce 决策才可作为附加条件；模型结果单独存在时不能把 ask 改为 allow | 不满足任一条件则保持 ask | FR-143/145 |
| BR-028 | 每个决策点三种模式：off（默认）、shadow、enforce。shadow 只记录不改变行为。从 shadow 升级到 enforce 须该决策点的评测达标（见 11.5.1），升级由用户修改配置完成，系统只给出建议 | 未达标不得在文档中标注为可 enforce | FR-144 |
| BR-029 | 失败策略按决策点类别固定：安全类失败时回退为 ask/deny，永不回退为 allow；路由类失败时回退到规则配置的默认角色；完成度类失败时视为「未验证」；上下文/工具裁剪失败时保留全部必需上下文/工具 | 回退并记录对应 `SY-DEC-*` 错误 | FR-146/147 |
| BR-030 | 阈值按错误后果分级配置，初始值仅为占位，须以代表性影子样本校准；JEV 的概率/置信度不等同于正确率，不得作为授权依据 | 未校准的阈值标记为 experimental；权限授权仍由规则与用户完成 | FR-143/148 |
| BR-031 | 状态最小化：发往决策服务的状态只含白名单字段（用户请求摘要、工具名、相对化的规范参数、风险类别），不含文件全文、密钥与主模型推理，并先经脱敏器。配置 `decision.egress = deny` 时禁止外发，回退到本地提供者或规则 | `SY-DEC-005` | FR-141/143 |
| BR-032 | 隔离原则：安全类决策的输入只含用户原始请求与被提议的调用，不含主模型的自由文本推理，避免模型「说服」决策器 | 构造输入时强制过滤，测试覆盖 | FR-143/145 |
| BR-033 | 每次决策必须产生 `decision` 事件并写入会话日志：决策点、问题版本、提供者与模型版本、概率分布、置信度、阈值、采取的动作、耗时、是否降级 | 缺失视为缺陷 | FR-146 |
| BR-034 | 单次决策超时初始设为 1500ms（WP-0 以 PoC 校准）；连续 5 次失败或超时则熔断 60 秒，期间直接走失败策略，并以事件通知；超时绝不意味着放行；熔断后以探测请求恢复 | `SY-DEC-001`、`SY-DEC-003` | FR-147 |
| BR-035 | 同一回合内对同一状态与问题去重；同一回合多个工具调用的门控请求合并为一次请求（每个调用一个问题）；缓存仅限同一会话且状态哈希相同 | - | FR-143 |
| BR-036 | enforce 模式下必须钉住决策模型的具体版本，不得使用别名（如 latest）；版本变更后须重新做一个周期的 shadow | `SY-DEC-006` | FR-141/144 |
| BR-037 | 决策拦截或升级为 ask 后，用户的最终选择记录为弱标签（同意或覆盖），仅本地存储，用于校准报告，默认不上传 | - | FR-148 |
| BR-038 | 工具集裁剪与上下文相关性：仅在工具数超过 40 时启用裁剪，必选工具集（read、edit、bash、ask\_user 等）不可裁剪；相关性只影响压缩时的保留优先级，不得删除 BR-013 规定的必保留项；失败回退为全量 | 回退并记录 | FR-145 |
| BR-039 | 级联：低置信度按配置逐级升级（deterministic fallback、替代 judge、sota/主 LLM、用户），每级结果均记录；高后果操作最终必须落到用户或安全拒绝，不得由任何模型独立批准 | `SY-DEC-008`（info） | FR-149 |
| BR-040 | 规则建议：决策层可统计被用户反复批准的低风险调用，生成候选 allow 规则；必须经用户确认后才写入配置，不得自动写入 | - | FR-148 |

## 5.7 CLI 与服务化规则（v0.3 新增）

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-041 | serve 默认只绑定 127.0.0.1 或本地套接字（Unix socket、命名管道），要求 Bearer 令牌，令牌随机生成、文件权限 0600，拒绝跨域；绑定非回环地址须显式 `--host` 并提示风险 | `SY-SRV-001`、`SY-SRV-002` | FR-150/154 |
| BR-042 | 非交互模式遇到 ask 一律按 deny 并输出明确提示。退出码：0 成功且满足验收策略；1 一般错误；2 用法或配置错误；3 因权限拒绝未完成；4 达到预算、轮次或总时长上限；5 确定性验收失败/未通过；130 被中断 | `SY-CLI-001`、`SY-CLI-002` | FR-134/135 |
| BR-043 | 配置来源信任：项目级 `.syaocode/` 中声明的 MCP 服务器、钩子、插件在首次使用时须用户确认（首次使用信任），内容哈希变化后重新确认，防止打开不受信仓库即执行代码 | `SY-CFG-003` | FR-136 |

## 5.8 三角色 agents、goal 与 loop 规则（v0.3 新增）

| ID | 规则 | 违反时处理 | 关联 FR |
| --- | --- | --- | --- |
| BR-044 | 角色职责边界：hyaki 与 sota 只读（工具集限于 read、glob、grep、web\_fetch 及向 hyaki 的读取请求），不得写入与执行；common 持有写与执行权限且受 BR-001 约束；任何角色的权限不得超出父会话（BR-022） | `SY-AGT-003` | FR-160/163/164 |
| BR-045 | 交接只传交接物：角色间只传 Brief、Plan、Result，不传完整历史；交接物须通过 schema 校验，含来源引用、预算与验收条件 | 校验失败重试一次，仍失败 `SY-AGT-002` | FR-165 |
| BR-046 | 摘要保真：hyaki 摘要必须原样保留用户明确要求、错误与失败信息、数字与标识符与路径等精确字面量；关键事实须可回溯到原文位置；原文永不删除且可再读 | 抽检不达标则评测失败 | FR-162 |
| BR-047 | 升级条件：common 在同一步骤连续失败 2 次、验收条件不明确、或决策层判断复杂度高时，请求 sota 重规划；一次任务中 sota 最多被唤醒 3 次（可配置） | `SY-AGT-004` | FR-164/168 |
| BR-048 | 预设档位与成本护栏：economy、balanced、max 三档定义各角色的默认模型与思考强度；每个角色可设预算上限；sota 的费用占比超过配置比例时发出 `budget.warning` | 事件告警，达上限则终止该角色调用 | FR-166/167 |
| BR-049 | hyaki 触发阈值：待读取内容超过 20k token 或涉及 10 个以上文件时才走 hyaki，小输入由 common 直接读取，避免多一跳 | - | FR-161/162 |
| BR-050 | goal 完成判定：确定性验收器优先；没有验收器时只能产生“语义上可能完成”的标记，不得等同于确定性通过。低置信/验收失败视为未完成；续跑上限默认 5 次，达限必须停止并生成报告 | `SY-RUN-001`、`SY-RUN-005` | FR-170 |
| BR-051 | loop 规则：必须有 `maxRuns` 且提供 `until` 或事件触发条件；无人值守时 ask 一律 deny/暂停，不能等待不存在的交互；单轮和总计均受费用、轮次、时长上限约束；连续失败 3 轮、权限不足、工作区/分支变化时暂停并报告 | `SY-RUN-002`、`SY-RUN-003`、`SY-RUN-004` | FR-171/172 |
