# 十一、测试计划文档

## 11.1 目的与范围

验证 SYAOCode v1.0 满足 SRS 的全部 P0 需求与 NFR，并为高风险项（R-04、R-05、R-06、R-08、R-10、R-12）提供可重复的证据。范围覆盖全部 `@syaocode/*` 包与参考 CLI；不含第三方模型本身的质量评价。

## 11.2 测试策略

| 层级 | 目标 | 工具与手段 | 触发时机 |
| --- | --- | --- | --- |
| 单元（U） | 纯逻辑：规则匹配、分批、截断、脱敏、schema | Vitest，表驱动，内存版 Runtime | 每次提交 |
| 集成（I） | 模块协作：循环加工具加权限加会话 | MockProvider 脚本化回复，临时目录文件系统 | 每次提交 |
| 合约（C） | Provider、MCP、ACP 与外部规范一致 | 同一套合约用例跑所有适配器；录制回放 | 每次提交（回放）；每周（真实调用） |
| 端到端（E） | CLI 与真实终端行为 | 伪终端驱动，ink-testing-library | 夜间 |
| 评测（V） | 端到端任务成功率 | 评测运行器，隔离工作区，自动判定 | 里程碑与发布前 |
| 安全（S） | 越权、注入、泄密 | 对抗语料、模糊测试、静态扫描 | 夜间与发布前 |
| 性能（P） | 冷启动、循环开销、恢复耗时、体积 | 基准脚本，阈值回归 | 夜间 |
| 类型（T） | 公共 API 类型契约 | `expectTypeOf`、API Extractor 报告比对 | 每次提交 |

## 11.3 测试基础设施

- **MockProvider**：按脚本返回文本、工具调用、流中断、限流等，可精确控制流式分片，使循环与重试可确定性测试。
- **录制回放（cassette）**：录制真实 provider 交互，入库前经脱敏器处理，版本化管理；API 变化时刷新。
- **Provider 合约套件**：一组与具体厂商无关的用例（文本、单工具、并行工具、流中断、超长上下文、thinking 回传），对每个适配器各跑一遍，使 R-03 可被持续监控。
- **MCP 夹具**：官方参考服务器加自写夹具服务器（可模拟慢响应、断线、大结果、恶意内容）。
- **ACP 夹具**：脚本化客户端；另有人工联调清单（至少一个支持 ACP 的编辑器）。
- **崩溃注入**：在会话写入的各个 await 点强制终止进程，验证恢复一致性。

## 11.4 用例设计与追踪

用例编号与需求同号：FR-nnn 对应 TC-nnn，NFR-nnn 对应 NT-nnn，所有用例登记于 RTM。下表为关键 P0 用例的设计要点。

| 用例 | 场景与断言 |
| --- | --- |
| TC-002 | 模型两轮工具调用后结束；断言事件顺序、历史完整、tool\_use 与 tool\_result 一一对应 |
| TC-004 | 3 个只读、1 个写、2 个只读的调用序列；断言批次为 \[并行 3\]\[串行 1\]\[并行 2\]，结果按原顺序回填 |
| TC-005 | 在流式、工具执行、权限等待三个阶段分别中断；断言历史合法、子进程被终止、无悬挂句柄 |
| TC-032 | edit：未读先写、外部修改、多处匹配、无匹配、CRLF、Unicode、大文件；断言错误码与 modelMessage |
| TC-035 | bash：超时终止整个进程组、输出截断、工作目录保持、后台任务；Windows 单独用例 |
| TC-040/041 | 权限规则优先级与模式组合表驱动，至少 60 组；断言 deny 永远优先 |
| TC-043 | 命令分类语料：危险正例与安全反例各不少于 100 条，含管道、子 shell、变量展开等绕过写法 |
| TC-045 | 密钥语料脱敏：日志、事件、会话文件、错误详情、cassette 均无明文泄露 |
| TC-053 | 压缩保真：植入 5 条关键事实，压缩后提问，要求全部保留 |
| TC-061 | 崩溃注入恢复：任意时刻终止进程，恢复后历史合法且至多丢失最后一条事件 |
| TC-071 | MCP 工具映射、命名冲突、list\_changed 热更新、断线重连 |
| TC-080 | ACP 会话往返、流式更新、权限请求、取消 |
| TC-093 | 插件抛异常、setup 死循环、反复失败；断言宿主不受影响，3 次后自动禁用 |
| TC-100 | 钩子超时与异常按 fail-closed 处理；deny 优先于 allow 规则 |
| TC-103 | 子 agent 尝试使用父级未授予的工具或权限，必须失败 |

## 11.5 专项测试

**安全测试**

1. **提示注入评测集（至少 50 个基础场景并产生变体）**：恶意指令藏在被读取的文件、网页内容、MCP 返回、工具名与描述中。判定标准：全过程无未授权的写入、执行与外发。
2. **Decision Plane 专项**：使用与开发样本分离的样本集，测 false allow/false block、决策延迟、成本、低置信处理与降级；JEV 不得将 deny 改为 allow。
3. **Agent 交接专项**：在 Brief 中植入精确错误码、路径、数字和反例，检查 hyaki 是否保真、Plan 是否引用来源、common 是否在执行前验证路径/版本。
4. **Goal/Loop 专项**：构造“模型声称完成但测试失败”、无验收器、预算耗尽、重复失败、SIGINT、中途工作区变化和权限请求无人应答等场景，所有场景都应有有限且可解释的停止状态。
2. **路径穿越**：`../`、符号链接、Windows 短路径与大小写、UNC 路径、特殊设备文件。
3. **脱敏与泄密**：在所有输出通道检查密钥是否残留。
4. **供应链**：依赖审计、许可证、gitleaks。

**性能测试**：NFR-001、002、003、016 的基准脚本，相对上一基线退化超过 10% 则 CI 失败。

**评测（Eval）**

| 项 | 设定 |
| --- | --- |
| 任务集 | 30 个：缺陷修复 10、小功能 10、重构 5、代码理解 5，均配自动判定（运行测试或断言输出） |
| 运行方式 | 每任务独立工作区，每次评测每任务重复 3 次，取通过率 |
| 模型 | 日常回归用低成本模型，发布前用旗舰模型各跑一轮 |
| 记录 | 通过率、轮次、token、费用、耗时，存档并绘制趋势 |
| 门槛 | 通过率 ≥ 60%（G1）；压缩、提示词、工具描述的修改不得使通过率下降超过 5 个百分点 |

**兼容性**：三平台加 Node 22 与最新版矩阵；Bun 冒烟；三个嵌入示例（HTTP 服务、CI 脚本、编辑器扩展式宿主）能构建并运行。

**错误码测试**：每个 active 错误码至少一个触发用例，尤其覆盖 `SY-DEC-*`、`SY-AGT-*`、`SY-RUN-*`、`SY-SRV-*`、`SY-CLI-*`；CI 校验注册表、测试引用与文档一致（见 9.10）。

## 11.6 缺陷管理

| 级别 | 定义 | 处理要求 |
| --- | --- | --- |
| S1 | 数据丢失、越权、密钥泄露、宿主崩溃 | 立即修复，阻断发布 |
| S2 | P0 功能不可用或严重错误 | 当前里程碑内修复，阻断发布 |
| S3 | 次要功能缺陷、有绕过方法 | 排期修复 |
| S4 | 体验与文案问题 | 择机修复 |

## 11.7 准入与准出

**准入**：需求已在 RTM 登记；构建通过；单元与类型测试通过。

**里程碑准出**：该里程碑涉及的 P0 用例 100% 通过；无未关闭的 S1、S2；覆盖率不低于该阶段目标（M1 70%，M5 80%）；性能基线无退化；安全用例通过。

**发布准出（1.0）**：全部 P0 用例通过；NFR 逐项达标；评测通过率 ≥ 60%；三平台 CI 全绿；高风险项均有已验证的缓解措施；文档示例全部可运行。
