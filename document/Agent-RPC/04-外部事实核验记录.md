## 5. 官方 SDK 事实与选型矩阵（2026-10-27 ~ 2026-10-28 核验）

### 5.1 三个官方 TypeScript SDK 的硬事实

| # | SDK | 版本（核验日） | Node | zod 关系 | 与本仓 `zod 3.25.76` 的兼容性 |
| --- | --- | --- | --- | --- | --- |
| S1 | `@modelcontextprotocol/core`（MCP SDK v2 线） | `2.4.0` | `>=20` | **dependency `zod ^4.2.0`**（硬依赖，非 peer） | ❌ 不兼容：会嵌套安装第二份 zod；跨边界传 schema 有类型风险 |
| S2 | `@a2a-js/sdk` | `1.3.0` | `>=20` | **无 zod**（运行时仅 `jose ^6.2.3`） | ✅ 兼容：不触碰本仓 schema |
| S3 | `@agentclientprotocol/sdk` | `2.0.2` | 未声明 `engines` | **peer `zod ^3.25.76 \|\| ^4.0.0`** | ✅ 兼容：本仓解析出的 `3.25.76` 正好满足下界 |

> `zod` 版本事实：本仓 `package.json` 声明 `^3.24.0`，`pnpm-lock.yaml` 实际解析为 **`zod@3.25.76`**；`zod` 最新为 `4.6.7`，其 `exports` 同时提供 `./v3` 与 `./v4` 子路径。因此"MCP SDK 需要 zod 4"并非不可跨越：可选方案是把本仓依赖升到 `zod ^4.6.7` 并把 import 改为 `zod/v3`（保留 v3 API）。该方案需 PoC 验证（`zodToJsonSchema` 依赖 `_def` 内部结构，v3/v4 布局不同但当前实现已同时兼容两种）。

### 5.2 MCP SDK v2 的已知行为（决定是否隔离使用）

| # | 事实 | 影响 |
| --- | --- | --- |
| S4 | v2 是稳定线，实现 2026-07-28 规范；取代 v1 单包 `@modelcontextprotocol/sdk`；拆成 9 个包（`server`/`client`/`core`/`node`/`express`/`hono`/`fastify`/`server-legacy`/`codemod`） | 依赖面变大；只能隔离在适配器子路径 |
| S5 | API 变更：`.tool()/.prompt()/.resource()` → `registerTool/registerPrompt/registerResource`；`setRequestHandler(Schema,…)` → `setRequestHandler('tools/call',…)`；`extra` → `ctx`；`McpError` → `ProtocolError` | 跟随成本；但也意味着生态在迁移 |
| S6 | 传输：`NodeStreamableHTTPServerTransport` / `WebStandardStreamableHTTPServerTransport`；`createMcpHandler(factory)`、`serveStdio(factory)` | 服务端接入样板 |
| S7 | **版本陷阱**：v2 默认仍发 2025 `initialize`；`versionNegotiation` 默认 `'legacy'`，`'auto'` 探测 `server/discover` 后回落，`{pin:'2026-07-28'}` 不回落 | 必须显式配置，否则"以为在跑 2026-07-28，其实在跑 legacy" |
| S8 | `createMcpHandler` 每请求新建 server、不持状态、无 `Mcp-Session-Id` | 与 2026-07-28 无状态模型一致 |

### 5.3 A2A / ACP SDK 的可用性

| # | 事实 | 影响 |
| --- | --- | --- |
| S9 | A2A SDK 提供 `./client`、`./server`、`./client/grpc`、`./server/grpc`、`./server/express`、`./server/database` 与 **`./compat/v0_3/*`** | 三种绑定 + 0.3 兼容开箱可用；`jose` 已在依赖里，AgentCard JWS 可复用 |

### 5.4 选型决策（分协议）

> **2026-10-28 落地记录**：实现最终统一采用**自研最小 JSON-RPC 层**（见 `05-实现评估与结论.md §6`）；下表保留为备选路线与互通测试参照。注意本节事实**已复核成立**：`@modelcontextprotocol/server@2.4.0` 存在、硬依赖 `zod ^4.2.0`、支持 `2026-07-28`（tarball 实测 `server/discover` 148 处、`resultType` 226 处）。


| 协议 | 决策 | 理由 | 回退 |
| --- | --- | --- | --- |
| **MCP** | **隔离使用官方 SDK v2，适配器内封装**；显式 `versionNegotiation`；不把本仓 Zod schema 传过边界（用 JSON Schema/纯对象） | wire 复杂度最高（`_meta` 信封、MRTR、tasks 扩展、subscriptions/listen、双时代）；官方实现可降低协议漂移风险 | 若嵌套 zod 造成类型/构建阻塞，回退到自研最小 client/server（03 §3.4 Plan B），只覆盖 `server/discover` + `tools/list` + `tools/call` + MRTR |
| **A2A** | **使用官方 `@a2a-js/sdk` 1.3.0**，包装在 `ProtocolAdapter` 之后 | 无 zod 冲突；官方 proto 类型 + JWS + 三绑定 + v0.3 兼容 | 若 SDK API 与治理钩子冲突，自研 JSON-RPC 子集（11 个方法） |
| **ACP** | **使用官方 `@agentclientprotocol/sdk` 2.0.2**，默认 v1 稳定入口 | peer zod 与本仓 3.25.76 兼容；v1/v2 入口分离 | 若 SDK 生命周期钩子不足，自研 stdio JSON-RPC 子集 |

> **原则**：SDK 只出现在 `@syaocode/protocols` 的对应子路径内，作为可选 peer/依赖；`@syaocode/rpc` 与 `@syaocode/core` 永不依赖任何协议 SDK。这同时满足 02 的 ADR-R9（适配器用官方 SDK/schema）与 ADR-R11（内核 host-agnostic）。
