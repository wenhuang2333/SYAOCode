> **说明**：本文是早期关于"npm + `npx` 发布形态"的讨论记录，**不是完整产品文档**。
> 完整的产品定位、用户、场景、功能规格、指标与路线图见 [`产品文档-详细版.md`](产品文档-详细版.md)。

可以，而且 **SYAOCode 非常适合通过 npm + `npx` 发布**。你最终希望用户做到：

```
npx syaocode
```

甚至：

```
npx syaocode init
npx syaocode
npx syaocode --version
```

就可以直接启动你的 Agent CLI。

npm 本身就是通过 `package.json` 的 `bin` 字段把 npm package 暴露成 CLI 命令的；发布后，用户可以通过 npm registry 获取这个包。[npm 文档](https://docs.npmjs.com/cli/commands/npm-publish/?utm_source=chatgpt.com)

不过对于你这个项目，我建议**从一开始就按照“真正的 CLI 产品”来设计，而不是简单把一个 Node 项目上传 npm**。

# 二、首先你需要一个 npm 账号

注册 / 登录 npm 后：

```
npm login
```

然后：

```
npm whoami
```

确认当前账号。

npm 官方目前允许公开发布 unscoped package，例如：

```
syaocode
```

也允许发布 scoped package：

```
@你的用户名/syaocode
```

unscoped 包天然是 public；scoped 包默认是 restricted，需要显式发布为 public。[npm 文档](https://docs.npmjs.com/about-public-packages/?utm_source=chatgpt.com)

------

# 三、我建议你的 npm 包直接叫 `syaocode`

如果这个名字没有被别人占用，你最终最好做到：

```
npx syaocode
```

而不是：

```
npx @xxx/syaocode
```

因为前者非常适合作为一个真正的 CLI 品牌。

你可以先检查：

```
npm view syaocode
```

如果提示不存在，再考虑占用这个名字。

同时也可以检查：

```
npm search syaocode
```

# 五、CLI 的 package.json 非常重要

例如：

```
{
  "name": "syaocode",
  "version": "0.1.0",
  "description": "JEV-powered agentic coding CLI",
  "type": "module",
  "bin": {
    "syaocode": "./dist/index.js"
  },
  "files": [
    "dist",
    "README.md",
    "LICENSE"
  ],
  "engines": {
    "node": ">=22"
  },
  "scripts": {
    "build": "tsup",
    "dev": "tsx src/index.ts",
    "test": "vitest",
    "prepublishOnly": "npm run build"
  },
  "repository": {
    "type": "git",
    "url": "git+https://github.com/你的用户名/SYAOCode.git"
  },
  "license": "MIT"
}
```

最关键的是：

```
"bin": {
  "syaocode": "./dist/index.js"
}
```

npm 官方的 `bin` 字段就是用来把 package 中的可执行文件暴露成 CLI 命令的。[npm 文档](https://docs.npmjs.com/cli/configuring-npm/package-json/?utm_source=chatgpt.com)

# 六、入口文件

`src/index.ts`：

```
#!/usr/bin/env node

import { startCLI } from "./cli.js";

await startCLI();
```

注意第一行：

```
#!/usr/bin/env node
```

它非常重要。

因为 npm 安装后需要知道：

> 这个文件应该交给 Node.js 执行。

构建以后：

```
dist/index.js
```

仍然应该保留这个 shebang。

# 七、然后你就可以本地模拟 npx

不要一开始就发布。

先：

```
npm run build
```

然后：

```
npm pack
```

你会得到类似：

```
syaocode-0.1.0.tgz
```

然后：

```
npm install ./syaocode-0.1.0.tgz
```

测试：

```
syaocode
```

或者：

```
npx ./syaocode-0.1.0.tgz
```

npm 官方也建议发布前检查最终 package 内容，可以使用：

```
npm pack --dry-run
```

来确认哪些文件会被包含。[npm 文档](https://docs.npmjs.com/cli/commands/npm-publish/?utm_source=chatgpt.com)

------

# 八、确认没问题之后才正式发布

如果是：

```
syaocode
```

这种 unscoped public package：

```
npm publish
```

即可。

npm 当前文档说明，直接发布 public package 需要账户具备相应的 2FA 或 granular access token 配置。[npm 文档](https://docs.npmjs.com/creating-and-publishing-unscoped-public-packages/?utm_source=chatgpt.com)

如果你以后决定：

```
@syao/syaocode
```

则：

```
npm publish --access public
```

scoped public package 必须明确设置 public。[npm 文档](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages/?source=post_page-----f282030cd5de--------------------------------&utm_source=chatgpt.com)

# 九、发布以后

假设：

```
name = syaocode
version = 0.1.0
```

那么用户就可以：

```
npx syaocode
```

或者：

```
npx syaocode@latest
```

也可以：

```
npm install -g syaocode
```

然后：

```
syaocode
```

npm 的 `latest` dist-tag 是默认标签，因此用户不指定版本时会解析到对应的 latest 版本。[npm 文档](https://docs.npmjs.com/cli/commands/npm-publish/?utm_source=chatgpt.com)

# 十、但你的 SYAOCode 有一个非常重要的问题

这也是我最建议你现在提前考虑的：

```

# 十三、GitHub Actions 自动发布

当你正式做 SYAOCode 时，我强烈建议：

```
GitHub
   │
   │ git tag v0.1.0
   ▼
GitHub Actions
   │
   ├── install
   ├── lint
   ├── test
   ├── build
   ├── npm pack
   └── npm publish
```

也就是说以后你根本不需要手动：

```
npm publish
```

而是：

```
git tag v0.1.0
git push --tags
```

自动发布。

npm 官方也推荐 CI/CD 场景考虑 trusted publishing，并支持生成 provenance 信息，这比长期保存 npm token 更适合正式项目。[npm 文档](https://docs.npmjs.com/creating-and-publishing-unscoped-public-packages/?utm_source=chatgpt.com)

# 十五、还有一个对你非常重要的架构问题

因为你以后要做 **Tauri Desktop**，所以我建议你从现在开始把 npm 包拆成：

```
@syaocode/core
@syaocode/agents
@syaocode/decision
@syaocode/mcp
@syaocode/tools
@syaocode/providers
@syaocode/protocol
```

然后：

```
syaocode
```

只是 CLI。

这样以后：

```
                    @syaocode/core
                          │
             ┌────────────┼────────────┐
             ▼            ▼            ▼
            CLI        Desktop       Server
             │            │            │
           Node.js       Tauri       Node.js
             │            │
             ▼            ▼
          React/TUI    React GUI
```

**这一步非常关键。**

因为未来 Desktop 不应该：

```
Desktop → 调用 CLI
```

而应该：

```
Desktop → 调用 @syaocode/core
CLI     → 调用 @syaocode/core
```

这样你的 CLI 和 Desktop 才是真正的**两个客户端**。

                    SYAOCode
                        │
                 Agent Runtime
                  TypeScript
                        │
       ┌────────────────┼────────────────┐
       │                │                │
      JEV              LLM             Tools
       │                │                │
       └────────────────┼────────────────┘
                        │
                     Agents
                ┌───────┼───────┐
                │       │       │
              hyaki    sota   common
                │       │       │
                └───────┼───────┘
                        │
                 Client Protocol
                        │
              ┌─────────┴─────────┐
              │                   │
             CLI               Desktop
              │                   │
            npm/npx          Tauri + React
```

其中 npm 这一层：

```
syaocode
```

负责：

> **“让任何开发者无需 clone GitHub、无需手动安装依赖，只需要一个 npx 命令就能运行 SYAOCode。”**

而真正长期维护的核心则是：

```
@syaocode/*
```

这一组 packages。

这会比把所有代码塞进一个 `syaocode` npm package 里更适合你后面继续做 **MCP、JEV、hyaki/sota/common、Goal/Loop、Desktop**。
