## 3. C-1 修复（安全回归，最高优先级）

**缺陷**：`policy.ts` 的 `presetVerdict()` 只在 `capability.protocol === 'local'` 时咨询 core `PermissionEngine`。因此客户写一条普通 `mcp://**` allow，就等于关闭了 **BR-006 危险命令库 / BR-003 工作区围栏 / 敏感路径清单**。

**本机复现**（修复前）：`rm -rf /`、`/etc/passwd`、`~/.ssh/id_rsa` 经 MCP 边缘 **3/3 succeeded，peer 被调用 3 次**。

**修复**：安全语义是**所有协议的底线**，不是 `local://` 的特例。`presetVerdict` 对所有能力生效，且与规则在**同一优先级**参与裁定（deny > ask > allow），因此只能收紧、不能被 ARF 的 allow 放宽。

**修复后**：三例全部 `denied`，peer 调用 **0** 次。回归测试：`redteam.test.ts` 的「C-1」两条（正向边缘 + ACP 反向）。

### 4.1 与官方 SDK 的真实互通（只有真实互通能发现的 4 个缺陷）

用官方 `@modelcontextprotocol/client@2.4.0` + `{ mode: { pin: '2026-07-28' } }` 驱动 `syao serve --mcp --http`。**首次运行连续失败 4 次**，每次暴露一个自指测试不可能发现的问题：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `SyntaxError: Unexpected token 'C', "Content-Le"...` | HTTP 响应体写入 stdio `Content-Length` 帧 | HTTP 通道改为 `json-lines`，响应体只回裸 JSON |
| 2 | `missing required resultType` | modern 规范的列表结果必须带 `resultType` 判别符 | `tools/list`、`resources/list`、`prompts/list`、`resources/read`、`prompts/get` 全部补上 |
| 3 | `ttlMs` 类型错误 | 列表结果必须带 `ttlMs`/`cacheScope` 缓存提示；工具必须带 `inputSchema` | 统一 `cacheHint()`；`inputSchema` 缺省为宽松对象 schema |
| 4 | `no provider for local://tools/read satisfies the route constraints` | 内置工具 provider 用 `ttlMs: 60_000`，60 秒后变 `down` 被路由过滤 | 内置工具 `ttlMs: 0`（进程内固定目录不应过期） |

**最终结果：`scripts/interop-mcp-official.mjs` → 8/8 通过**（modern era 协商、`server/discover`、缓存提示、`tools/list`、`inputSchema`、`tools/call` 真实文件内容）。

复现方式见该脚本头部注释。

## 5. C-5 修复（交付门禁）

- 新增 `scripts/check-build-artifact.ts`（`pnpm build:check`）：检查每个包有 dist 入口、**dist 中不存在 `from './x.ts'` 的运行时导入**、并**以发布态解析**启动构建后的 CLI（用 `publishConfig.exports` 建影子 `node_modules`，复制 dist，链接 zod 等外部依赖）。
- CI 补齐 `lint:rpc`、`build`、`build:check` 三道门禁。

> 结论：发布产物**可以**运行（`syao v0.2.0-dev`）。审计观察到的 `ERR_MODULE_NOT_FOUND` 是**开发态 `exports` 指向 `src/*.ts`** 的必然结果，不是发布缺陷；但"build 通过 ≠ 产物可运行"这一点成立，现在由 `build:check` 守住。
